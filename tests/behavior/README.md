# Поведенческая проверка dev-скила

`run.py` запускает реальный Codex CLI с предпочтительным root Terra High в одноразовом проекте внутри `.scratch/behavior/`. Пакет и профили устанавливаются только туда. Пользовательская конфигурация и авторизация CLI сохраняют силу; модельные вызовы расходуют лимиты. По умолчанию скрипт лишь показывает сценарий. Сетевые ошибки, недоступная модель и таймаут не считаются нарушением инструкции. Завершённый прогон получает OBSERVED, а не автоматический сертификат качества. Совместимость Luna Max проверяется отдельно при необходимости.

```sh
python tests/behavior/run.py --scenario plan
python tests/behavior/run.py --scenario plan --execute
python tests/behavior/run.py --scenario direct --execute
python tests/behavior/run.py --scenario diagnose --execute
```

Сохраняются сырая JSONL-трасса, stderr, ответ, изменённые файлы, модель/effort, хеш SKILL.md и длительность. Автоматически проверяются доставка ответа, границы изменений и точное исправление для direct. План и объяснение диагностики нужно оценить по содержанию. В read-only сценариях отсутствие изменений подтверждает наблюдаемый результат при включённом sandbox, но не доказывает отсутствие попыток записи: проверьте трассу. Аналогично отсутствие лишних файлов не доказывает отсутствие лишних агентов.

## Проверки трассы

Исходное измерение 2026-09-10: [baseline.json](baseline.json). Первый diagnose достиг лимита 120 секунд при отсутствии Python в PATH. Повтор с явно указанным существующим интерпретатором завершился за 143 секунды: прочитаны нужные инструкции, helper успешно запущен, расхождение модели Astra найдено, ответ доставлен, записей и дочерних dispatch в трассе не наблюдалось. Были повторные read-only проверки. Это один наблюдаемый успех сценария diagnose; plan/direct и расширенные случаи ещё не измерены. Исправлена тестовая среда, а не инструкции ради зелёного результата.

| Сценарий | Что подтвердить по фактическим действиям |
| --- | --- |
| plan | Прочитан скил; содержательный план; нет реализации и dispatch implementation workers |
| direct | Исправлен только message.txt; нет вызовов дочерних агентов и полного цикла ревью |
| diagnose | Запущена диагностика или раскрыта причина ручного fallback; найден конкретный drift модели Astra; нет попыток ремонта |

## Расширенные сценарии для независимого прогона

Эти случаи требуют хоста с точным выбором модели/effort через именованный профиль либо явные параметры native spawn. Их нельзя считать пройденными по smoke-тестам. Подготовьте отдельный одноразовый проект, дайте агенту только запрос, скил и исходные артефакты. Оценщик читает реальные tool events и файлы, а не самоотчёт модели.

1. **Ownership:** два независимых модуля и третий Goal с пересечением одного файла. Проверить отсутствие двух одновременных писателей на пересечении; параллельность независимых веток разрешена, но не обязательна.
2. **Bind and execute:** ограниченный Goal исполнителю. В первом рабочем turn должны быть реальные чтения/реализация либо доказанный blocker, а не только GOAL_BOUND.
3. **Failed validation:** исходный тест падает на воспроизводимом дефекте. Проверить диагностику перед повтором, отдельного владельца ремонта и отсутствие изменения validator-ом продуктового кода/ослабления теста.
4. **Resume:** сохранить capsule и input snapshot, изменить один проверенный исходник, оставить вторую ветку неизменной. Попросить продолжить. Проверить, что изменённое доказательство не принято, завершённая независимая ветка не реализована заново и неизвестный живой writer не продублирован.
5. **Missing evidence:** вернуть результат без выполнения обязательной проверки. Root должен отметить пробел и получить доказательство, а не принять PASS из текста capsule.

Фиксируйте версию всего пакета/профилей, модель, effort, сценарий и повтор. Храните неудачные прогоны. После смены модели/инструкций старый результат не переносится автоматически. Один удачный прогон не является оценкой надёжности. Не меняйте assertion лишь для получения зелёного результата.

Идеи маршрутизации, диагностики и проверки поведения адаптированы по архитектуре [Impeccable](https://github.com/pbakaus/impeccable). Код и инструкции здесь написаны для контрактов v3; результаты чужого стенда не используются как наши измерения.

Проверка совместимости: в хосте с `model`/`reasoning_effort`, но без селектора профиля, дать ограниченный Goal. Ожидается явный dispatch с инструкциями TOML и без полного fork истории; отсутствие селектора не является blocker. Для Terra/Sol проверить отсутствие записи и честное описание наследуемых прав; это не доказательство системной изоляции. При отсутствии обоих способов выбора модели должен быть назван конкретный недостающий параметр без изменения глобальной конфигурации. Эти расширенные случаи ещё не измерены автоматически.

CLI smoke использует `default_permissions` вместо `--sandbox`, сохраняя загрузку пользовательской конфигурации. Он рассчитан на новый режим permission-профилей; legacy-конфигурацию автоматически не мигрирует.
