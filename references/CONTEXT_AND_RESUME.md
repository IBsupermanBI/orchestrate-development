# Context and resume

For substantial work, Root keeps a compact record in a project-approved local artifact area: outcome, authority pointers, acceptance, ownership, implementation policy (`auto` or `sol-only`), selected route and reason, prior attempts and unresolved gap, completed/pending Goals, primary success signal, blockers, validation evidence and next action. This is working context, not a replacement specification system or a hook ledger.

On resume, read current user intent and project instructions, inspect live workspace/Git state without destructive repair, verify the relevant evidence inputs, invalidate only evidence whose inputs changed, and bind only pending work. A missing record or unavailable task is unknown, not complete. Do not repeat completed work or broad validation merely because the conversation resumed.

Retain an established `sol-only` policy across follow-ups and resume until the user explicitly permits Astra. If the record is absent, recover the latest explicit routing restriction from available conversation context before selecting a route; do not treat omission as permission to clear a known restriction.

When Root or either implementation worker needs wide factual exploration, formulate one bounded Scout question. The returned `RESEARCH_CAPSULE` is compressed into Goal pointers; a fresh sufficiently narrow map avoids duplicate reconnaissance.
