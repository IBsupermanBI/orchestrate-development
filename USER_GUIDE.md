# Руководство пользователя V5

## Начало работы

Установите пакет по [README](README.md), выберите `gpt-6-sol` с effort `medium` и передайте ожидаемый результат, границы работы, известные контракты и критерии приёмки. Root исследует доступные факты и запрашивает только решения, принадлежащие пользователю.

Пример:

```text
$orchestrate-development-v5 run
В проекте /path/to/project добавь повторную отправку неуспешного импорта.
Сохрани формат данных и существующие права доступа.
Приёмка: успешный повтор не создаёт дубликаты; ошибка видна пользователю;
проверены основной сценарий и повтор после сбоя.
```

Отображаемое имя — `Orchestrate Development`. При установке нескольких версий используйте `$orchestrate-development-v5`, чтобы выбрать нужную. Наличие профиля TOML само по себе не подтверждает фактическую модель агента. Root проверяет поддерживаемый способ привязки перед первым dispatch и сообщает о недоступном маршруте.

## Режимы

| Режим | Результат |
| --- | --- |
| `run` | Выполнение до подтверждённого результата; режим по умолчанию для запроса на выполнение |
| `plan` | План без dispatch реализации |
| `resume` | Проверка текущего состояния, актуальности доказательств и продолжение незавершённой работы |
| `diagnose` | Диагностика выбранной установки без записи |

Вызов без результата приводит к уточнению цели. Обсуждение workflow само по себе не запускает разработку.

## Экономичный режим: `no astra`

Добавьте модификатор к режиму или явно запретите Astra обычным текстом:

```text
$orchestrate-development-v5 run no astra
<результат, scope и критерии приёмки>
```

Также допустимы `plan no astra` и `resume no astra`. Без модификатора новая работа использует политику `auto`; с ним — `sol-only`. Это команды в запросе к skill, а не аргументы Python-скриптов.

При `sol-only` единственный исполнитель реализации — GPT-6 Sol Medium. Root не переключается на Astra даже после неудачной попытки Sol и не обходит запрет через другой профиль или skill. Он диагностирует причину, уточняет подход или разбивает Goal в пределах согласованного scope. Если продолжить обоснованно нельзя, сообщает блокер и незавершённый результат. Критерии приёмки и effort сохраняются.

Scout, Luna Repair для ограниченных исправлений, независимый Sol review, Luna validation и Sol High Gate остаются доступными. Поэтому `no astra` не означает «все роли на Sol».

Запрет действует на текущую работу и сохраняется при продолжении и `resume`, даже если модификатор не повторён. Для возврата к обычной маршрутизации явно скажите: «Разрешаю Astra для этой работы». Сам skill не снимает запрет. Если запрет введён во время работы Astra, Root завершает её владение безопасно, сохраняет diff и передаёт остаток Sol.

## Как выбирается исполнитель

По умолчанию работает **Sol Medium**. Root передаёт ограниченный Goal: результат, участок владения, контракты, критерии приёмки, основной наблюдаемый сигнал, проверки и краткую причину выбора маршрута.

В обычной политике `auto` **Astra Low** получает Goal, когда требуется разрешить существенную неопределённость способа реализации. Например, нужно согласовать взаимодействие нескольких подсистем или выбрать устройство интерфейса в пределах утверждённого сценария. У Astra нет дополнительных полномочий на изменение продукта или публичного контракта.

| Ситуация | Действие |
| --- | --- |
| Понятный контракт и существующий паттерн, включая работу с данными | Sol Medium |
| Неизвестно расположение реализации, но сам подход ясен | Целевой поиск или Scout; затем выбор исполнителя |
| Неясное взаимодействие механизмов или инвариантов | Astra Low с указанным пробелом и ожидаемым результатом |
| Sol проверил конкретный подход, но основной сигнал не улучшился | Root диагностирует причину; Astra при пробеле в рассуждении о реализации |
| Проверка заблокирована окружением или входными данными | Устранение блокера, без автоматической замены модели |
| Причина дефекта установлена, исправление ограничено, контракт стабилен | Luna Repair xHigh |

В `auto` Astra можно выбрать сразу. Обязательного пробного запуска Sol нет. Маршруты не определяются словами «легко», «сложно» или «важно». Effort фиксирован; Astra Medium/High не используются.

При смене исполнителя Root завершает владение предыдущего автора, сохраняет полезный diff и передаёт доказательства, попытку и оставшийся пробел. Два автора не меняют пересекающийся участок одновременно.

## Исследование, реализация и приёмка

Root отвечает за WHAT, декомпозицию и интеграцию; выбранный исполнитель — за HOW. Sol и Astra имеют одинаковый контракт реализации и сами проверяют изменяемый код.

Scout на Luna Medium вызывается только для ограниченного фактического вопроса, когда готовой узкой карты недостаточно. Его могут вызвать Root, Sol Worker, Astra Worker и Gate. Scout возвращает `RESEARCH_CAPSULE`: пути, связи, проверенные факты, неопределённость и рекомендуемые прямые чтения. Он не пишет код, не проектирует решение и не создаёт агентов. Repair, Reviewer и Validator также не делегируют.

Исполнитель возвращает `EVIDENCE_CAPSULE` с diff/revision, изменениями, решениями, проверками и рисками. Root принимает отдельный Goal или назначает исправление, решение либо review.

Независимый review выполняет свежий Sol Medium агент на стабильной границе. Это отдельный агент, даже если реализацию делал Sol; автор не проверяет себя в роли reviewer. Review назначается по риску или этапу, без обязательного вызова на каждое изменение.

После стабильной интеграции и необходимых исправлений Luna xHigh Validator проверяет критерии и возвращает `PASS`, `FAIL` или `INCOMPLETE`. Он не исправляет код и тесты. Sol High Gate затем принимает окончательное решение по этапу; Root исполняет его и сообщает результат. Отсутствие достаточных доказательств не считается успехом.

## Что будет в отчёте

Принятый результат, основной наблюдаемый сигнал, реально выполненные проверки, использованные маршруты и остаточные риски. Сообщение исполнителя «готово» не заменяет приёмку. Экономия V5 пока является гипотезой: её оценивают по завершённым задачам, качеству и фактическим затратам, без вымышленных метрик.

## Обновление и диагностика

V5 устанавливается рядом с V4; для отката достаточно снова явно выбрать сохранённую V4. V3-помощник архивирует только V3 и теперь устанавливает V5; команды и ограничения приведены в [README](README.md).

```sh
python scripts/orchestration_doctor.py diagnose --project /path/to/project
```

Команда не изменяет файлы и не проверяет доступность моделей. Совпадение установленной копии с исходной не доказывает корректное поведение агентов.
