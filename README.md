# Orchestrate Development V5

Явно вызываемый Codex skill для разработки с разделением реализации, независимого review, проверки и приёмки. V5 использует GPT-6 Sol Medium по умолчанию и сохраняет Astra Low для реализации с существенной неопределённостью. Архитектура остаётся неглубокой: добавлен только один маршрут реализации.

## Модели и ответственность

| Роль | Модель | Effort | Ответственность |
| --- | --- | --- | --- |
| Root | `gpt-6-sol` | `medium` | WHAT, декомпозиция, интеграция, приёмка отдельных Goals |
| Основной исполнитель | `gpt-6-sol` | `medium` | HOW и ограниченная реализация |
| Специализированный исполнитель | `gpt-6-astra` | `low` | Та же ответственность при существенной неопределённости реализации |
| Scout | `gpt-6-luna` | `medium` | Ограниченное исследование без записи |
| Repair | `gpt-6-luna` | `xhigh` | Исправление с установленной причиной и стабильным контрактом |
| Независимый reviewer | `gpt-6-sol` | `medium` | Review без реализации и приёмки |
| Validator | `gpt-6-luna` | `xhigh` | Финальная проверка и доказательства, без исправлений |
| Final Gate | `gpt-6-sol` | `high` | Финальная приёмка этапа без записи |

Sol подходит, когда результат, место изменения, паттерн репозитория, контракты и критерии приёмки достаточно ясны. Astra выбирается по конкретной неопределённости: архитектурные альтернативы, неясное поведение внутренних механизмов, связанные изменения через несколько границ, проектирование UI/UX или существенные вопросы инвариантов данных и безопасности. Само название области или субъективная «сложность» не определяет маршрут.

В обычном режиме, если содержательная попытка Sol не улучшила основной наблюдаемый результат, Root исследует причину и передаёт реализацию Astra, когда оставшийся пробел требует более сильного рассуждения. Недоступное окружение или неутверждённое продуктовое решение устраняются отдельно. Astra Medium/High и динамическая лестница effort отсутствуют.

Это рабочая гипотеза об экономике полного цикла, а не обещание измеренной экономии. Семейство и параметры моделей сверены с [официальным каталогом OpenAI](https://developers.openai.com/api/docs/models); фактическое связывание роли с моделью проверяется на хосте перед dispatch.

## Установка

Требуется Python 3.11+. Внешние зависимости для установки и тестов пакета не нужны.

```sh
python install.py --project /path/to/project
python install.py --project /path/to/project --apply
```

Первый вызов показывает план без записи — эквивалент dry-run / WhatIf. Второй устанавливает skill в `.agents/skills/orchestrate-development-v5/` и восемь профилей `v5-*` в `.codex/agents/`. Установщик не меняет `AGENTS.md`, hooks или Git. При конфликте сначала изучите план; `--apply --force` сохраняет заменяемые файлы в `.backups/`.

Для пользовательской установки используйте `--user`, при необходимости `--home /path/to/codex-home`. Файлы размещаются в `skills/` и `agents/` выбранного Codex home.

### Переход с V4 и более ранних версий

V5 устанавливается рядом с V4: прежние skill и профили сохраняются. Выберите V5 явно через `$orchestrate-development-v5`; для возврата используйте сохранённую V4. Автоматического переноса или удаления V4 нет. Установленные V2 также не затрагиваются.

Сохранён отдельный opt-in помощник для V3:

```sh
python scripts/upgrade_from_v3.py --project /path/to/project
python scripts/upgrade_from_v3.py --project /path/to/project --apply
```

В этой версии он устанавливает V5 и архивирует только известные V3 assets и резервные копии, содержащие только V3-профили, в `.agents/skills/archive-orchestrate-development-v3-pending-removal/<timestamp>/`. Изменённые V3-файлы сохраняются; смешанные резервные копии остаются на месте. Обратный переход выполняется вручную из архива после проверки. Помощник не мигрирует V4. Для user scope доступны `--user --home`.

## Использование

Выберите Root `gpt-6-sol` / `medium`, затем вызовите `$orchestrate-development-v5` с результатом и критериями приёмки. Отображаемое имя остаётся `Orchestrate Development`; в интерфейсе с упоминаниями доступен `@Orchestrate Development`. При нескольких установленных версиях используйте точное имя skill.

Доступные режимы: `run` (по умолчанию), `plan`, `resume`, `diagnose`. Для экономичного режима добавьте `no astra`:

```text
$orchestrate-development-v5 run no astra
<результат и критерии приёмки>
```

`no astra` запрещает Astra для реализации: остаётся Sol Medium, в том числе при существенной неопределённости и отсутствии прогресса. Запрет сохраняется при продолжении и `resume` до явного разрешения пользователя использовать Astra. Scout, Luna Repair, независимый review, validation и Gate сохраняют свои роли и effort. Это инструкция маршрутизации внутри skill; установщик по-прежнему включает оба профиля реализации.

Root выбирает Sol или Astra для каждого Goal. Root, оба исполнителя и Gate могут вызвать ограниченный Scout; остальные роли — leaf. На пересекающемся участке работает один автор. Независимый review выполняет свежий агент. После интеграции и необходимых исправлений следуют Luna validation и Sol High Gate.

## Проверка пакета

```sh
python scripts/validate_package.py
python -m unittest discover -s tests -v
python scripts/orchestration_doctor.py diagnose --project /path/to/project
```

Диагностика сравнивает установленную копию с выбранным исходным пакетом без записи. Она не проверяет доступность моделей и не доказывает качество разработки. Пакет самодостаточен: соседние проекты, Loop Review, hooks и telemetry не требуются. GitHub CI проверяет пакет на Linux, Windows и macOS.
